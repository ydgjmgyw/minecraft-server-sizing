## 先定开什么服，再决定买多大

服务端核心决定了内存门槛和 CPU 压力，选错了后面全是坑。

| 玩法 | 服务端 | 内存门槛 | 要注意的 |
| --- | --- | --- | --- |
| 原汁原味 | Mojang 官方 server.jar | 4 核 8G | 无插件无模组，最省心 |
| 插件服 | Paper（Spigot 高性能分支） | 4 核 8G | 兼容大部分 Bukkit / Spigot 插件 |
| 轻度模组 | Fabric | 4 核 8G 起 | 轻量、更新快，适合追最新版本 |
| 重度模组 | Forge | 8G 起 | 高版本要先跑 `-installServer` 生成启动脚本 |
| 模组 + 插件双修 | Mohist | 8G 起 | 只更新到 1.20.2 |
| 整合包 | Forge / Fabric + 整合包服务端 | 10G 起，10 人以上 16G | ATM9 近 400 个模组，启动要几分钟 |
| 基岩版 | BDS / Nukkit / PMMP | 看人数，比 Java 版省 | 默认 19132 端口，UDP 协议 |

Mohist 这条值得单独提醒。它能同时加载 Forge 模组和 Bukkit 插件，看起来是模组和插件双修玩家的理想选择，但版本停在 1.20.2，1.21 之后的整合包用不了。买机器之前先确认你要玩的整合包是什么版本，别等装完了才发现核心对不上。

整合包吃内存的程度超出很多人预期。ATM9 包含近 400 个模组，8G 内存开不起来，开 swap 勉强能启动但会拖慢；10G 是起步线，10 人以上直接上 16G。

## CPU 单核 600 分这条线，和 Java 版本对照表

「要高主频」这句话太虚，换成可验证的指标：CPU-Z 单核跑分 600 分以上。这条线来自雨云自己的开服教程，14900K、13900K、7950X、9950X 都是过了线的机型。反面例子是机房淘汰的 E5 系列，核心数看着唬人，单核弱，跑 1.18 以上的模组服 TPS 能掉到个位数，玩家走两步回弹一步。

装错 JDK 是新手最常见的启动失败原因，服务端还没跑起来就报 `UnsupportedClassVersionError`。对照下表选：

| 需要的 Java 版本 | Minecraft 游戏版本 |
| --- | --- |
| JDK 8 | 1.7 及以下 |
| JDK 11 | 1.8 ~ 1.16 |
| JDK 17 | 1.17 ~ 1.19 |
| JDK 21 | 1.20 及以上 |
| JDK 25 | 26 及以上 |

1.20 之后的版本统一用 JDK 21。网上有些老教程写「1.16 以上用 JDK 17」，那是 1.19 时代的说法，照抄会启动失败。1.21 的服就装 JDK 21，别犹豫。

## NAT 还是独立公网 IP：朋友连进来会不会卡

NAT 机是多个用户共用一个公网 IP，靠端口映射把内网服务暴露出去。雨云的 NAT 机型给 15 个端口，开一个 MC 服绰绰有余：MCSManager 面板占 2 个，MC 服务端占 1 个，还剩 12 个。

独立公网 IP 贵一截，好处是独占 IP、独享 150G 防御，适合对外公开、担心被打的服，或者同一台机器上还要跑网站、语音服之类需要多个端口的服务。

线路差异比 IP 类型更影响「朋友进来卡不卡」：

- **江苏镇江**：NAT 网络，多用户共用公网 IP，可以加钱选独立公网 IP。
- **浙江宁波**：有便宜的独立公网 IP，但是电信单线，高峰期联通、移动用户延迟会明显升高。
- **镇江和宿迁**：都是 BGP 线路，各运营商的用户延迟都比较低。

如果你的朋友以电信为主，宁波没问题；朋友来自三大运营商，镇江或宿迁更稳。这条比省几十块钱重要。

端口映射的实操在雨云控制台的「NAT 端口映射」里，新建规则时协议选 **TCP+UDP**，内网端口填对应的服务端口，外网端口用默认随机值，范围是 10000–60000。每个人的外网端口都不一样，教程里截图上的数字只能当参考，照抄一定连不上。

## 动态计费和固定计费怎么选

**动态计费**按 CPU 实际占用浮动，CPU 占用率超过 20% 时开始额外计费，每天有免费额度。适合偶尔开服的场景，比如每周五晚上和朋友玩两小时，平时机器闲着，费用会比固定计费低不少。

**固定计费**是一口价，不管你开不开、CPU 跑不跑满。适合 7×24 挂着的服，尤其是加了插件、有红石机器、玩家随时可能上线的社区服。

年付 7 折只对固定计费有意义。动态计费本来就是按用量算的，年付锁定后反而失去灵活性。如果你的服确定要长期开，固定计费加年付是最省钱的组合；如果只是先试试水，动态计费按月跑一周，看实际用量再决定。

## 开服实操：最小必要步骤

**端口清单**先记牢：

| 服务 | 端口 | 协议 |
| --- | --- | --- |
| MCSManager 面板 | 23333 | TCP |
| MCSManager 守护进程 | 24444 | TCP |
| Minecraft Java 版 | 25565 | TCP |
| Minecraft 基岩版 | 19132 | UDP |

NAT 机型要把这几个端口逐一映射出去，基岩版的 19132 一定要按 UDP 放行，只开 TCP 会连不上。

**系统选 Debian 12**，软件安装那一步不要勾选，装完用 SSH 进去装 MCSManager。装好后访问 `http://公网IP:23333`（NAT 机换成 23333 映射出的公网端口），进面板的「节点」里把远程节点 IP 填成服务器公网地址，端口填 24444 映射出的公网端口。

**装对应版本的 JDK**，然后新建实例，启动命令可以照抄这条：


java -Xms1G -XX:MaxRAMPercentage=90.0 -XX:+UseZGC -jar server.jar nogui


- `-Xms1G` 是初始堆内存，让 JVM 启动时就预分配，避免运行中频繁扩容。
- `-XX:MaxRAMPercentage=90.0` 限制 JVM 最多用系统内存的 90%，留 10% 给系统和面板。想固定成 7G 也可以换成 `-Xmx7G`。
- `-XX:+UseZGC` 启用 ZGC 垃圾回收器，大内存、低延迟，适合长时间运行的服务端。这个参数只有 JDK 15 及以上才正式支持，低版本要去掉。
- `nogui` 不启动图形界面。

首次启动会提示 `You need to agree to the EULA`，去 `eula.txt` 把 `false` 改成 `true`，再点开启。看到 `Done` 就启动完成了。

**给管理员权限**：在面板终端输入 `op 玩家ID`。

**离线服要改 `online-mode`**：编辑 `server.properties`，把 `online-mode=true` 改成 `false`。这一步有代价，关闭正版验证后所有人都能进你的服，被 ban 了换个 ID 照样回来，容易被人搞破坏。开公开服的话，用插件或模组做白名单比直接关验证稳妥。

**关服一定用 `stop` 命令**，直接关进程会回档，玩家建的东西可能白搭。

**客户端连接**填 `公网地址:端口`，中间是英文冒号。中文冒号连不上，这是新手最常踩的坑之一。
